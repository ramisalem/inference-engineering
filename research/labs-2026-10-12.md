## A. Environment recommendation [M1]

- Python: pin **3.12 via uv** (leave Homebrew 3.14.7 alone). Evidence: genai-bench requires <3.13, aiperf requires <3.14, vllm-metal and the vLLM macOS CPU wheel are cp312-only, av/scipy need >=3.12 (PyPI JSON, fetched 2026-10-12).
- Commands (uv docs): `uv python install 3.12` ; `uv venv --python 3.12` ; `source .venv/bin/activate` ; `uv pip install mlx-lm`
- Homebrew formulas: `llama.cpp` (0.6.0), `ollama` (0.40.3, already installed), `macmon` (0.9.0), `hf` (2.2.0, replaces huggingface-cli), `whisper.cpp` (1.9.5, renamed from whisper-cpp), optional `text-embeddings-inference` (1.9.4, arm64 bottle). Source: https://formulae.brew.sh/api/formula/<name>.json
- Two venvs: `.venv-labs` (3.12: mlx-lm, aiperf, locust, transformers, sentence-transformers, diffusers, torch 2.14.1) and `.venv-convert` (only for llama.cpp `convert_hf_to_gguf.py`, which pins torch==2.11.0).
- Do not install: Xcode (~10 GB, only needed to open .gputrace), full vLLM source build.
- Disk budget (verified sizes, Hugging Face API / whisper.cpp README, 2026-10-12):

| Item | Size |
|---|---|
| Qwen3-0.6B GGUF Q8_0 | 0.64 GB |
| Qwen3-4B GGUF Q4_K_M | 2.50 GB (Q8_0 4.28 GB) |
| mlx-community/Qwen3-0.6B-4bit | 0.34 GB |
| mlx-community/Qwen3-4B-4bit | 2.26 GB |
| whisper.cpp base / small | 142 MiB / 466 MiB |
| torch 2.14.1 macOS wheel | ~0.13 GB (plus deps) |
| Target total at any time | under 10 GB |

Do not keep Qwen3-4B bf16 (8.04 GB) locally; use it only on Colab/Kaggle. Ollama keeps a separate store (`~/.ollama/models`) from the HF cache (`~/.cache/huggingface/hub`) and v0.40.2 keeps backup copies when it upgrades old models, so duplicates are likely. Clean with `hf cache ls` / `hf cache prune` / `ollama rm`.

## C. Verified setup commands

[M1] llama.cpp (formulae.brew.sh/api/formula/llama.cpp.json; tools/server/README.md in ggml-org/llama.cpp):
```
brew install llama.cpp
llama-server -hf <user>/<model>:<tag> --port 8080 --metrics -np 4
llama-server -m target.gguf -md draft.gguf --spec-type draft-simple      # composed from documented flags
./build/bin/llama-quantize in-bf16.gguf out-Q4_K_M.gguf Q4_K_M
```
- Binaries on macOS: llama-server, llama-cli, llama-completion, llama-bench, llama-batched-bench, llama-quantize, llama-perplexity, llama-imatrix, llama-gguf-split, llama-tokenize, llama-mtmd-cli. New unified `llama` binary also exists (`llama serve`, `llama bench`).
- Endpoints: /v1/chat/completions, /v1/completions, /v1/embeddings, /v1/models, /v1/responses, /health, /slots; `/metrics` only with `--metrics`. Metrics are `llamacpp:*` (prompt_tokens_total, tokens_predicted_total, predicted_tokens_seconds, requests_processing, requests_deferred, spec_decode_*); no KV-usage gauge documented.
- Default port is 8080 at v0.6.0 but 9931 on master/nightlies. Always pass `--port`.

[M1] MLX (https://github.com/ml-explore/mlx-lm README, SERVER.md):
```
uv pip install mlx-lm        # mlx 0.32.3, mlx-lm 0.32.0 (needs Python >=3.11, macOS >=14)
mlx_lm.generate --model mlx-community/Qwen3-4B-4bit --prompt "hello" --draft-model mlx-community/Qwen3-0.6B-4bit --num-draft-tokens 3
mlx_lm.convert --model <hf_repo> -q --q-bits 4 --q-group-size 64
mlx_lm.cache_prompt --model <repo> --prompt - --prompt-cache-file p.safetensors
mlx_lm.server --model <repo> --port 8081
```
`mlx_lm.server`: OpenAI /v1/chat/completions, /v1/completions, /v1/models, /health; no /metrics, no embeddings; "not recommended for production"; supports `--draft-model`, `--prompt-cache-size`.

[M1] Ollama 0.40.3 (https://github.com/ollama/ollama/releases, docs/api): timing fields are nanoseconds: total_duration, load_duration, prompt_eval_count, prompt_eval_duration, eval_count, eval_duration. Decode tok/s = eval_count / eval_duration x 1e9. Env: OLLAMA_NUM_PARALLEL (default 1), OLLAMA_CONTEXT_LENGTH (default 4096), OLLAMA_KEEP_ALIVE (5m), OLLAMA_KV_CACHE_TYPE, OLLAMA_FLASH_ATTENTION. v0.40.0 runs supported models on MLX by default on Apple Silicon.

[M1] Monitoring: `brew install macmon` ; `macmon serve` exposes Prometheus /metrics on port 9090 (collides with Prometheus default port). asitop needs sudo.

[M1] PyTorch MPS: torch 2.14.1 (2026-09-30) has cp314 macOS arm64 wheels; MPS needs macOS 14+; no float64 on MPS; `PYTORCH_ENABLE_MPS_FALLBACK=1` (https://docs.pytorch.org/docs/2.14/notes/mps.html). Python 3.14 itself is fine for torch/mlx; 3.12 is chosen for tool compatibility.

[M1] vLLM: official docs say Apple silicon CPU backend is experimental, build from source, FP32/FP16 only, no prebuilt wheels (https://docs.vllm.ai/en/latest/getting_started/installation/cpu.html). The `vllm-project/vllm-metal` plugin (MLX-based, macOS 15+, cp312 wheels, stable 0.30.0) is the community Metal route; not recommended for a 16 GB first pass (M1 16 GB performance UNVERIFIED).

[T4] vLLM 0.31.0 (PyPI 2026-10-05; docs.vllm.ai installation/gpu): "compute capability 7.5 or higher (e.g., T4 ...)", Python 3.11-3.14, default wheels built with CUDA 12.9.
```
uv pip install vllm --torch-backend=auto
vllm serve Qwen/Qwen3-1.7B --dtype half --max-model-len 4096 --gpu-memory-utilization 0.85     # composed; flags standard, T4 fit not run
```
UNVERIFIED: which attention backend V1 picks on sm_75 (FlashAttention-2 does not run on Turing; see E); whether Colab/Kaggle drivers satisfy CUDA 12.9 wheels.

Benchmark client (https://docs.vllm.ai/en/latest/cli/bench/serve.html):
```
vllm bench serve --backend openai --base-url http://127.0.0.1:8000 --endpoint /v1/completions \
  --dataset-name random --random-input-len 1024 --random-output-len 128 --num-prompts 1000 --max-concurrency 32 --request-rate inf
```
Metrics selectable with `--percentile-metrics ttft,tpot,itl,e2el`; `--goodput` takes ttft/tpot/e2el SLOs. No macOS wheel on PyPI for vllm (sdist + Linux wheels only), so on the Mac use aiperf/locust as the client and run `vllm bench serve` on Colab/Kaggle.

Load tools (PyPI JSON, 2026-10-12): aiperf 0.13.0 (Python >=3.11,<3.14), genai-bench 0.0.5 (>=3.10,<3.13), locust 2.46.7 (>=3.11), guidellm 0.8.1 (>=3.10). Minimal commands for aiperf/genai-bench/locust/guidellm: UNVERIFIED (not fork-verified; read https://docs.nvidia.com/aiperf/ and https://sgl-project.github.io/genai-bench/ before the lab). Roadmap nodes name AIPerf (github.com/ai-dynamo/aiperf), Locust, genai-bench, NVIDIA GenAI-Perf (https://github.com/nilbuild/developer-roadmap, roadmaps/inference-engineering/content).

[M1] whisper.cpp (https://github.com/ggml-org/whisper.cpp): `whisper-cli -m models/ggml-base.en.bin -f samples/jfk.wav`; needs 16-bit 16 kHz WAV (`ffmpeg -i in.mp3 -ar 16000 -ac 1 -c:a pcm_s16le out.wav`); `whisper-server` exposes `/inference`; VAD via `--vad --vad-model ggml-silero-v6.2.0.bin`. Core ML encoder optional (3x faster, needs Xcode CLT + coremltools).

[M1] TEI on Mac (https://huggingface.co/docs/text-embeddings-inference/local_metal): `brew install text-embeddings-inference` ; `text-embeddings-router --model-id Qwen/Qwen3-Embedding-0.6B --port 8080`; Prometheus on `--prometheus-port` (default 9000).

## E. Risks and gotchas

1. [T4] **FlashAttention-2 does not run on Turing.** Official README: Ampere, Ada or Hopper only; bf16 needs those too; Turing points to a separate flash-attention-turing repo (https://github.com/Dao-AILab/flash-attention). Use `--dtype half`. Which backend vLLM falls back to on sm_75: UNVERIFIED.
2. [T4] **Triton:** PyPI triton 3.8.0 (2026-08-28) has Linux x86_64/aarch64 wheels only for cp310-cp314. Minimum compute capability and sm_75 limitations (e.g. no fp8): UNVERIFIED. No Triton on macOS.
3. [T4] SGLang on T4, TensorRT-LLM on T4/L4, torch CUDA wheel coverage of sm_60 (Kaggle P100) and sm_75: UNVERIFIED. PyTorch 2.14 ships CUDA 12.6/13.0/13.2 wheels (https://pytorch.org/blog/pytorch-2-14-release-blog/); check whether the P100 option still works before relying on it.
4. [T4] Profiling: torch.profiler works in principle but Nsight Systems/Compute availability and counter permissions on Colab/Kaggle: UNVERIFIED. PyTorch 2.14 removed the profiler `use_cuda` option (use `activities=[ProfilerActivity.CUDA]`).
5. [Kaggle 2xT4] TP=2 over PCIe without NVLink will be slower than 1 GPU for small models; works as a concept lab. Disaggregated prefill/decode on 2xT4: UNVERIFIED.
6. [M1] Port collisions: llama-server 8080 (v0.6.0), mlx_lm.server 8080, macmon 9090 vs Prometheus 9090, TEI metrics 9000. Always set ports.
7. [M1] llama.cpp flag churn: `--draft-max/--draft-min` removed; classic completion is `llama-completion`; many tutorials are stale.
8. [M1] Ollama: NUM_PARALLEL=1 means concurrent load tests queue; Homebrew service forces flash-attention and q8_0 KV cache; no Prometheus /metrics (issue #3144 open); MLX runner since v0.40 makes cross-version numbers incomparable.
9. [M1] mlx_lm.server loses batching with a draft model, `--kv-bits`, or per-request `seed`. Keep spec-decoding and throughput labs separate.
10. [M1] Wiring more memory (`sysctl iogpu.wired_limit_mb`) on 16 GB can starve macOS. Qwen3-4B 4-bit (2.3-2.5 GB) leaves plenty of headroom; 8B at 4-bit (~5 GB) is the practical ceiling for concurrency labs.
11. [M1] Docker Desktop on macOS: no Metal passthrough (UNVERIFIED here, widely documented); containerized servers are CPU-only arm64. Official `vllm/vllm-openai-cpu:latest-arm64` image exists (v0.31.0, 1.09 GB, Docker Hub API 2026-10-12); ARM CPU supports FP32/BF16/FP16.
12. Gated models (Llama 3.2) return an error without an HF token (confirmed for meta-llama/Llama-3.2-1B-Instruct config fetch); Qwen3 is ungated.
13. Model facts are time-sensitive: Ollama release notes mention qwen3.5/3.6/3.8, gemma4, embeddinggemma-2, and llama.cpp README demos Qwen3.5-0.8B-GGUF. Whether a newer family should replace Qwen3 in the course: UNVERIFIED.
